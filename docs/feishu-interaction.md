# 飞书交互约定

飞书与面板使用相同的会话归属：机器、项目目录、聊天程序和历史会话一起绑定。卡片上的“查看”不会偷偷切换话题绑定；“切换到此会话”才会改变后续消息去向。

## 卡片与操作

| 卡片 | 主要操作 | 说明 |
| --- | --- | --- |
| 任务进度 / 结果 | 查看最近对话、会话设置 | 运行时提供停止；确实执行失败且已受理的任务可手动继续。已完成任务不再显示停止或重复提交。 |
| 会话设置 | 查看最近对话、切换会话、新建会话 | 模型、账号、机器、聊天程序放在折叠设置中。旧会话仅可查看或明确切换，不会修改另一条当前会话。 |
| 最近会话 | 搜索、展开消息、切换到此会话 | 保留机器、项目、分支与近期问题，帮助辨认原终端会话。 |
| 新建会话 | 一次填写后“提交并开始” | 机器、项目、聊天程序、模型、文件工作方式和第一条问题一起提交；提交失败保留填写内容供修改重试。 |
| 选择 AI 模型 | 选择模型、刷新可用模型 | 仅此会话下一轮生效。当前任务不受影响。 |
| 切换聊天程序 | 切到 Claude Code / Codex 会话 | 接续目标程序上一次会话，无历史则新建。两边分别保留上下文，不合并对话。 |
| 切换执行机器 | 在此机器接续 | 优先接续该机器之前的会话，无历史则选择项目。目录按目标机器解析。当前机器与离线机器只显示状态。 |
| 账号与连接 | 使用其他账号、调整分配策略、刷新账号状态 | 明示全局路由影响范围，不把账号、模型和聊天程序混为一谈。 |

“查看最近对话”发送历史预览，长消息会提示截断，完整记录保留在面板。“会话信息”折叠区只放目录、会话 ID 等定位信息，不再与查看对话使用相同名称。

## 状态与恢复

- 蓝色：处理中、输出中、连接重试。
- 橙色：需要授权、等待确认、等待节点重连、执行结果待核对。
- 绿色：已收到明确完成事件。
- 红色：已收到明确执行失败。
- 网关重启后的旧卡片显示“进度同步已中断”，保留已同步回复和执行记录，删除失效的授权、停止和重放入口。中断同步不等于任务执行失败，也不声称执行已经完成。
- 终态卡片不能同时写“正在处理”。未知结果应先核对对话，避免重复执行已有操作。
- 接续原终端时，“断开飞书同步”只结束飞书监听，原终端任务继续运行；卡片会说明这一点。

## 操作安全与兼容

按钮继续沿用已有回调协议和会话引用，旧卡片仍可读取自己的历史。模型、账号、机器和聊天程序的设置入口会校验话题当前绑定；会话改变后，旧设置卡片要求重新打开，防止误改其他会话。权限和停止仍校验任务身份。

不主动批量重发历史消息。新卡片使用新的布局；待修复的中断卡片在网关恢复时清理旧状态。终端历史不被这些展示变更修改。

## 同一会话打开了多个终端

多个窗口可能同时登记同一个会话 ID。若仅有一个窗口处于 `idle` / `working` 对话状态，其余窗口均停在 `shell`，飞书会接续唯一的对话窗口；不会按目录遍历顺序或最近更新时间随意挑选。

连接建立后固定 PID、启动身份、PID 域与消息套接字。随后多开同一会话不会改变接续目标；原窗口退出或切换后也不会自动把消息转投另一个窗口。若一开始就有多个可对话窗口，会明确提示关闭多余窗口后再发送，此时尚未投递消息，也不会创建会话副本。

## 原终端自动接收，无需人工确认

在「IM 接入」勾选“原终端自动接收消息，无需回电脑确认”。这是显式开启的选项，默认关闭；开启后面板为该机器的 Claude Code 用户配置设置 `crossSessionInbound: "accept"`。飞书接续仍向同一原生进程投递，按消息 ID 去重，并等待原会话记录确认收到和生成回答，不复制会话、不代按终端确认键。

该配置属于 Claude Code 用户级接收策略，因此其他本机跨会话消息也会自动接收。它不改变飞书用户／群的授权规则，也不改变原终端工具权限。组织管理策略和项目中更严格的接收策略仍由 Claude Code 执行，面板不会覆盖这些策略或伪造发送者权限模式。

面板只保存接收键的原值作为撤销记录，不备份登录凭证或整个 settings.json；关闭选项会还原自己改动的键，并保留其他设置和用户后续的手动修改。已有用户级 `accept` 配置不由面板接管。配置解析失败或路径为符号链接时不覆盖原文件，界面显示原因。

实现参考：[Orca 的终端输入写入与确认机制](https://github.com/stablyai/orca/blob/main/src/main/runtime/terminal/input/runtime-terminal-writer.ts)。Orca 管理自己创建的 PTY，向相同进程写入输入并等待写入确认；对面板外已打开的独立终端，本项目使用 Claude Code 的原生消息入口与[官方跨会话接收设置](https://code.claude.com/docs/en/settings-reference#crosssessioninbound)。
