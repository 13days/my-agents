# 飞书交互约定

飞书与面板使用相同的会话归属：机器、项目目录、聊天程序和历史会话一起绑定。卡片上的“查看”不会偷偷切换话题绑定；点「切换」后，后续消息会进入所选会话。

## 找会话和查命令

发送 `/sessions 关键词`。每行用名称、机器、引擎、项目和最近活动帮助你辨认会话，点行尾「切换」后可直接追问。「会话详情」收起分支、创建时间、目录和按轮次排列的用户消息。

发送 `/help` 可直接点「找会话」或「新建任务」，也可按「新建与接续」「任务执行中」「引擎、模型与账号」「聊天与运行位置」查命令。简洁群只显示其权限范围内的文字帮助，Markdown 回复模式也有文字版。面板「帮助」使用相同的飞书命令目录。企业微信的 `/new`、`/whoami` 和 `/help` 可在帮助中的「企业微信」查看。

## 谁能让机器人回复

打开「聊天软件 → 飞书 → 访问权限」。已配对或手动勾选的账号属于授权名单。打开“允许已授权账号在任意群使用”后，这些账号可以在机器人已加入的任意多人群直接 @ 它。群主也按账号授权判断。只有一位真人时，飞书应用已发布群消息和群信息读取权限且网关能确认人数，就可以免 @。

勾选具体的群会授权群内成员，并开放详细任务卡和会话操作。只开启“允许所有群的成员使用”时，未单独勾选的群使用文字回复。“允许所有人私聊”只影响私聊。禁用账号同时拦截私聊和群聊。

## 卡片与操作

| 卡片 | 主要操作 | 说明 |
| --- | --- | --- |
| 任务进度 / 结果 | 查看最近对话、会话设置 | 运行时提供停止；确实执行失败且已受理的任务可手动继续。已完成任务不再显示停止或重复提交。 |
| 会话设置 | 查看最近对话、切换会话、新建会话 | 模型、账号、机器、聊天程序放在折叠设置中。旧会话仅可查看或明确切换，不会修改另一条当前会话。 |
| 最近会话 | 搜索、会话详情、切换 | 保留机器、项目、分支与近期问题，帮助辨认原终端会话。 |
| 使用帮助 | 找会话、新建任务 | 其余命令按工作场景展开，按钮保留发起人与话题绑定。 |
| 助理建议 | 确认全部行动、暂缓、忽略 | 展开可查推荐依据和后续记录，较长的行动须到助理页核对。 |
| 新建会话 | 一次填写后“提交并开始” | 机器、项目、聊天程序、模型、文件工作方式和第一条问题一起提交；提交失败保留填写内容供修改重试。 |
| 选择 AI 模型 | 选择模型、刷新可用模型 | 仅此会话下一轮生效。当前任务不受影响。 |
| 切换聊天程序 | 切到 Claude Code / Codex 会话 | 接续目标程序上一次会话，无历史则新建。两边分别保留上下文，不合并对话。 |
| 切换执行机器 | 在此机器接续 | 优先接续该机器之前的会话，无历史则选择项目。目录按目标机器解析。当前机器与离线机器只显示状态。 |
| 账号与连接 | 使用其他账号、调整分配策略、刷新账号状态 | 明示全局路由影响范围，不把账号、模型和聊天程序混为一谈。 |

“查看最近对话”发送历史预览，长消息会提示截断，完整记录保留在面板。任务卡先展示答复。最底部的署名行末尾可以展开“详情与操作”，查看本轮问题、实际模型、代理、执行机器、工作区、会话 ID 和工具记录。这里的“执行机器”指运行本轮 CLI、读写项目文件的机器。已有会话沿用绑定的机器，新话题默认执行机可在飞书连接设置中查看。任务发起人可以在有正文的成功任务卡中点“详情与操作 → 生成分享卡”，再用飞书转发生成的只读卡片。简洁文字回复没有此按钮。

## 状态与恢复

- 正常处理时先显示简短进度，有输出就直接展示正文。
- 橙色：需要授权、等待确认、等待节点重连、执行结果待核对。
- 已完成时直接显示最终答复，“详情与操作”内可核对状态和耗时。
- 红色：已收到明确执行失败。
- 网关重启后的旧卡片显示“进度同步已中断”，保留已同步回复和执行记录，删除失效的授权、停止和重放入口。中断同步不等于任务执行失败，也不声称执行已经完成。
- 终态卡片不能同时写“正在处理”。未知结果应先核对对话，避免重复执行已有操作。
- 接续原终端时，“断开飞书同步”只结束飞书监听，原终端任务继续运行；卡片会说明这一点。

## 操作安全与兼容

按钮继续沿用已有回调协议和会话引用，旧卡片仍可读取自己的历史。模型、账号、机器和聊天程序的设置入口会校验话题当前绑定；会话改变后，旧设置卡片要求重新打开，防止误改其他会话。权限和停止仍校验任务身份。

不主动批量重发历史消息。新卡片使用新的布局；待修复的中断卡片在网关恢复时清理旧状态。终端历史不被这些展示变更修改。

## 同一会话打开了多个终端

多个窗口可能同时登记同一个会话 ID。若仅有一个窗口处于 `idle` / `working` 对话状态，其余窗口均停在 `shell`，飞书会接续唯一的对话窗口；不会按目录遍历顺序或最近更新时间随意挑选。

连接建立后固定 PID、启动身份、PID 域与消息套接字。随后多开同一会话不会改变接续目标；原窗口退出或切换后也不会自动把消息转投另一个窗口。若一开始就有多个可对话窗口，会明确提示关闭多余窗口后再发送，此时尚未投递消息，也不会创建会话副本。

## 原终端自动接收，无需人工确认

在「IM 接入」勾选“原终端自动接收消息，无需回电脑确认”。这是显式开启的选项，默认关闭；开启后面板为该机器的 Claude Code 用户配置设置 `crossSessionInbound: "accept"`。飞书接续仍向同一原生进程投递，按消息 ID 去重，并等待原会话记录确认收到和生成回答，不复制会话、不代按终端确认键。

该配置属于 Claude Code 用户级接收策略，因此其他本机跨会话消息也会自动接收。它不改变飞书用户／群的授权规则，也不改变原终端工具权限。组织管理策略和项目中更严格的接收策略仍由 Claude Code 执行，面板不会覆盖这些策略或伪造发送者权限模式。

面板只保存接收键的原值作为撤销记录，不备份登录凭证或整个 settings.json；关闭选项会还原自己改动的键，并保留其他设置和用户后续的手动修改。已有用户级 `accept` 配置不由面板接管。配置解析失败或路径为符号链接时不覆盖原文件，界面显示原因。

实现参考：[Orca 的终端输入写入与确认机制](https://github.com/stablyai/orca/blob/main/src/main/runtime/terminal/input/runtime-terminal-writer.ts)。Orca 管理自己创建的 PTY，向相同进程写入输入并等待写入确认；对面板外已打开的独立终端，本项目使用 Claude Code 的原生消息入口与[官方跨会话接收设置](https://code.claude.com/docs/en/settings-reference#crosssessioninbound)。

## 后台 Agent 与阶段回复

原终端的 `end_turn` 只表示一次模型回复结束，不代表后台工作全部结束。面板会关联本次请求实际启动的异步 Agent 和后台命令：阶段回复显示后继续监听，卡片保持“等待后台任务”；收到所有相关任务的结束通知后，显示“等待原会话汇总”。只有原会话给出汇总、写入本轮结束记录且回到空闲状态，才显示完成。

任务结束通知必须来自 CLI 的系统事件，且任务 ID 必须属于本次请求。用户文本中粘贴的通知、其他会话的通知以及重复通知不会使任务提前完成。后台任务失败会显示工具失败状态，仍等待原会话汇总。卡片展示原终端会话名称和简短 ID，避免把另一个窗口的进度当作当前飞书会话。

### 转发本轮结果

展开已完成任务底部的「详情与操作」，点「生成分享卡」，机器人会在原位置回复一张只有结果正文和署名的卡片。预览后，用飞书的转发菜单选择收件人。特别长的答复会标为「摘录」。原任务的目录、工具记录和操作按钮留在任务卡上。只有发起人可以生成，每个任务生成一次。

任务卡、分享卡和按要求发送的业务卡都用一行署名，例如「my-agents · Claude Code · gpt-6.2 · 发送给：@林舟」。点「my-agents」打开项目仓库。引擎取自发起这轮任务的会话，收件人取自原提问人的飞书名称。

模型优先取本轮成功调用的代理记录，有推理强度时显示在模型名后。Claude Code 直接返回的模型名也可用于署名。仅知道请求或调用中的模型时会注明「请求」或「调用中」，暂无记录时显示「模型待确认」或「实际模型未记录」。
