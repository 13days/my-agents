# 当前架构与可靠性边界

本文件描述实际运行机制；`architecture-v2.md` 保留早期设计与迁移背景。

## 模块边界

- `core/session-manager`：校验输入、登记准备任务、选择执行位置、建立引擎会话、停止和恢复只读任务。
- `core/run-store`：每个 Run 的元数据与顺序事件日志。Conversation ID、原生 Session ID、Run ID、Message ID 分开记录。
- `node/execution-runtime`：执行节点持有 CLI，控制连接断开时保留已运行的任务；原控制方重连时按事件游标恢复。
- `node/rpc`：协商分块能力，将大消息拆成有界帧。旧节点不支持的大请求返回升级提示，避免拖断整条连接。
- `core/route-policy`：共享上游错误分类和冷却规则；各协议代理保留自身的鉴权及转换逻辑。
- `conversation-state.js`：Web 与 IM 共用任务状态归约，明确等待授权、重连、结果未知和已完成。
- `capture-index-worker`：后台读取历史抓包，代理及面板无需等待整个文件扫描完成。

## 状态和恢复

新任务在检出工作区之前登记为 preparing，并纳入忙碌检查。准备阶段可以按任务/会话 ID 取消；取消不会自动开始第一条问题。Git 检出在每个仓库内串行执行，支持空间估计和实际磁盘错误提示。

任务日志保存在数据目录的 `runs/<run-id>/`，文件权限为 0600，目录为 0700。日志和元数据包含用户对话，应按私人数据管理。输入及终态写入时执行文件同步；SSE 带有顺序 ID，支持 `Last-Event-ID` 增量回放。

服务进程重启后，没有确认的任务标记为 unknown，保留已记录事件，禁止自动重放输入。远端执行器进程仍存活时，可以按原生会话查找并重连，避免重复启动 CLI。

控制连接短暂断开不会停止具备恢复能力的节点上的已启动 CLI。模型中继保留监听端口，连接恢复后可以继续使用同一中继入口；断开时正在传输的 HTTP 请求仍可能失败，由客户端按既有重试策略处理。

## 集群

租约及选举时间间隔使用进程单调时钟，系统时间仅用于展示。租约有独立到期检查，并在操作入口核对当前有效性。测试覆盖时钟前跳、回拨与网络分区。

配置和会话检查点仍通过异步快照复制，**不承诺已确认消息的跨节点事务复制**。`/api/cluster` 明确报告 replication 模式。任务完整事件日志目前属于运行节点，本机事务日志不等于集群提交日志。

## 运维

`GET /api/health` 提供实际 Git 提交、启动时间、协议版本、历史索引状态与任务计数。`GET /api/tasks` 列出本机持久化任务及准备阶段状态。接口沿用面板统一鉴权。

升级应检查准备任务、引擎任务和执行器任务全部空闲，再逐台重启，核对 build.gitCommit 与节点连接。独立启动的终端 CLI 不应被面板升级关闭。

## 尚需单独实施的进程拆分

当前控制面、代理和部分本地执行仍在同一服务进程。后台索引消除了历史扫描阻塞启动，但尚不能保证重启整个节点服务时代理请求和本地托管 CLI 完全不受影响。SSH stdio 节点的进程也依赖 SSH 连接寿命；恢复能力适用于常驻 WebSocket/集群节点。

后续拆分独立代理与独立执行服务时，需要同步迁移凭证刷新所有权、会话事件持久化和升级协议，不能仅启动第二份面板竞争相同账号库和端口。当前部署仍遵守空闲后滚动升级。
