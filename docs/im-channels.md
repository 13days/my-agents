# IM 接入

my-agents 的定位是外部 Agent 的工作空间。IM 是使用这个工作空间的入口，飞书是一个渠道，不是整个产品的网关定义。

- 入口：`/im`，飞书 / Lark 配置与管理。
- 企业微信预留：`/im?channel=wecom`，明确显示尚未接入，不提供无效的配置表单。
- 兼容：旧 `/feishu` 页面地址跳转到 IM 接入；原 `/api/feishu`、配置文件、会话绑定、权限、消息记录与凭证位置保持兼容，无数据搬迁。

当前只有飞书 / Lark 适配器可用。界面渠道登记在 `index.html` 的公共 IM 入口；飞书管理界面保留在 `feishu-ui.js`，渠道专属字段与权限说明不放进公共入口。

后续新增企业微信等渠道时，应围绕以下边界实现：

1. 渠道适配器负责认证、接收消息、附件、卡片与回调，把平台事件转换成渠道无关的消息与操作。
2. 会话位置由渠道、机器人身份、群或私聊、话题组成，避免跨渠道串话。用户身份和权限也必须按渠道隔离。
3. 会话、引擎、模型、节点、任务队列与 worktree 继续复用现有工作空间和 session manager。
4. 平台能力不同：支持卡片选择器时提供交互；不支持时提供等价文字命令。不要把飞书卡片格式直接用在其他平台。
5. 接入新渠道时，从现有飞书网关中提取可复用的命令与绑定处理，而不是复制整份网关；当前飞书命令和卡片处理仍在飞书实现内，尚未完成通用 IM 路由抽取。

公共入口不代表所有渠道已实现；新增适配器必须独立验证接收、回复、回调、去重、权限、重连与会话恢复后才能标记为可用。
