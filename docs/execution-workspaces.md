# 面板、IM 主节点与执行机器

三个位置相互独立：

- 当前面板：浏览器打开的 my-agents 服务。Follower 也能使用页面。
- IM 主节点：取得多数派确认后连接机器人的成员。主节点切换不会把项目文件搬到新机器。
- 执行机器：保存代码、worktree 和 CLI 会话的机器，以稳定的机器 ID 记录在会话中。

「机器与引擎」分为集群与机器、项目与目录、引擎与账号。首页显示谁接收消息，以及各机器的面板连接和执行通道；任期、同步版本和连接错误放在诊断区。

## 默认目录和项目映射

`panel-workspaces.json` 保存每台机器的默认目录，以及同一项目在不同机器上的路径。保存时在目标机器上校验目录。未配置的项目位置不能作为可执行位置，不会改用另一台机器的目录。

已有会话固定在原机器执行。新会话可在设置中选择机器及项目映射。IM 的默认项目还有独立的默认执行机器设置。`local` 仅为当前进程内部别名；跨面板共享的绑定使用 `machineId`。

集群成员复用经过认证的成员连接提供执行通道，无需另开一个 SSH 节点才能回到原机器。现有独立 SSH / WebSocket 执行节点继续可用。

目录映射不复制代码、worktree 或 Claude/Codex 历史。切换执行机器应显式选择该机器上的项目和会话；原执行机器离线时，系统报告未连接，不会用同一个会话 ID 在另一台机器悄悄新建。原机器在线时，IM Leader 变更后可通过原机器上的 CLI 历史接续。

共享目录配置由有效主节点校验、写入并同步。Follower 的保存操作转交给主节点；没有有效主节点时不写入共享配置。

## 服务与接入

配置文件中的监听地址必须与实际运行服务一致。macOS 修改 LaunchAgent 环境后须重新 bootstrap，而不只是重启原配置里的进程。

集群采用预投票避免旧成员重复抬高任期，并处理更高任期响应。主节点状态与实际 IM 连接状态分别报告，连接可达数量不等于已经获得有效多数派租约。

这套配置保证执行位置不会因接收消息的主节点变化而被改写；它不承诺迁移正在执行的 CLI 进程，也不等同于对代码与磁盘做了跨机复制。
