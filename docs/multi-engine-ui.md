# 多引擎工作台

界面使用 my-agents 名称，npm 包名、启动命令和已有 Codex profile 名称保持兼容。Claude Code 与 Codex 在公共功能中平级展示，专属能力明确标注引擎归属。

## 页面结构

- 工作台：按引擎分别查看本机会话与用量。Claude 保留费用、预算和 Wrapped；Codex 展示 Token、缓存、模型、每日用量和带时间的额度快照，不跨引擎合并费用。
- 会话：按引擎筛选，两类会话都有来源标签。模型偏好分别记忆，切换引擎保留消息草稿。名称筛选支持两种引擎，全文搜索当前仅支持 Claude，界面说明此限制。
- 抓包：按引擎、调用类型、会话和关键词组合筛选。调用类型右侧显示数量，当前选中的类型不限制其他类型的计数。实时更新保留菜单和键盘焦点。旧列表接口缺少 engine 字段时，按明确的 Codex 代理来源标识兼容分类，不根据模型名猜测。
- 引擎与接入：Claude 管理代理商账号、路由策略和故障转移；Codex 管理本机登录与透传抓包。引擎与上游代理商是两个层级。
- 资源管理：Claude / Codex 切换真实资源目录。Claude 保留原有命令、技能、智能体、插件、工作流和配置。Codex 支持共享 `.agents/skills`、兼容 `.codex/skills`、AGENTS.md、AGENTS.override.md 和 config.toml，并支持项目范围。链接安装项与系统技能只读，API 限定文件和已知工作区。

单选下拉统一使用深色菜单，支持动态选项、禁用项、表单重置、键盘和弹窗顶层显示。搜索框关闭浏览器补全及拼写建议。手机导航采用图标布局，列表通过抽屉打开。

## 飞书网关

页面分为连接设置、访问权限和消息记录。状态区显示连接、机器人、CLI 版本和运行信息。切换页面保留表单输入，权限修改继续自动保存。

默认启动引擎用于未绑定位置的首条消息及未指定引擎的 `/new`，不会重绑已有会话。群、话题和私聊分别绑定；同一话题成员共享绑定。

| 操作 | 行为 |
|---|---|
| `/codex [问题]` | 切到 Codex；可直接带问题 |
| `/claude [问题]` | 切到 Claude Code；可直接带问题 |
| `/current` 或 `/engine` | 查看当前引擎与会话 |
| `/new codex`、`/new claude` | 强制新建对应引擎的会话 |
| `/sessions`、`/session` | 找回或切换已有会话 |
| `/projects` | 项目卡片中选择引擎与目录后新建 |

新会话卡片先显示当前项目与引擎，并提供切换项目和切换引擎；发送消息前不显示历史入口或临时会话 ID。旧卡片的临时 Codex ID 会映射到真实 ID，查看旧会话历史不改变当前引擎绑定。

每个位置分别记住两种引擎的会话，切换时接续各自上下文，无历史则新建。Codex 返回真实线程 ID 后同步更新绑定与引擎记忆；命令、卡片和重启后续接使用一致的引擎信息。旧引擎上下文不会传给另一引擎。

群内命令通常带 @机器人。解析器支持 SDK 文本、提及占位符和富文本 at 标签，只移除已确认的机器人前缀。命令在网关本地执行，普通正文、其他成员提及和 `/ask` 正文保持原意。详细卡片提供切换入口，简洁模式使用短命令并在普通回复末尾标注引擎。

联系人显示飞书姓名和群名，支持同步及本机备注。用户接口未返回姓名时，从该用户已发过消息的群成员信息补全，仅缓存已发现成员。取不到时可用备注；备注与官方名称分开保存，按应用隔离，清空备注可恢复官方名称。用户 ID 和消息统计分行显示，操作按钮保持紧凑。

SDK 错误只提取可读消息与错误码，不将对象强转后显示。已连接时主状态说明显示机器人与连接方式，非字符串错误不会覆盖正常连接信息。

## CLI 发现

源码不写入个人安装路径。Claude 优先探测 `npm prefix --global` 对应的有效安装，再回退到 PATH 中可执行的候选；支持 `CLAUDE_CLI` 显式覆盖。Codex 同样查询 npm 安装位置并比较候选版本。后台服务使用启动它的 Node 路径，保留显式 CLI 覆盖。安装位置按运行环境检测。

## 验证

161 项测试通过，覆盖多引擎资源、路径及写入边界、话题隔离、重启持久化、引擎往返接续、真实 Codex ID、带 @ 的短命令、名称补全与备注、错误格式和任意 npm prefix。

Chrome 验证桌面、平板和手机布局，以及下拉、表单、联系人、默认引擎设置和旧抓包列表兼容。测试写入使用临时目录或模拟响应，不调用真实模型。运行服务在无任务和活动代理连接时才重启加载更新。

历史统计、资源使用次数和旧抓包关联由后台线程处理；抓包首屏不等待关联完成，后续通过 revision 更新。会话及抓包等长列表每页 80 项，筛选覆盖完整数据集，分页切换不再次请求历史。并行的相同 GET 请求合并，列表使用 DocumentFragment 一次替换，加载时显示状态提示。

Codex 流式事件和历史回放展示 CLI 返回的公开思考摘要，详细飞书卡片同步展示；简洁模式保持普通文字回复。CLI 请求启用自动摘要，模型未返回时不生成占位思考内容，工具调用也只展示实际事件。运行版本以网关选中的 CLI 为准，子进程 PATH、CLAUDE_CLI 和终端包装函数保持一致。

会话消息展示发送/回复时间及助手本轮耗时：Claude 与 Codex 历史读取原始时间，Codex 优先使用 task_complete 的 duration_ms；实时事件保存服务端时间和 turn/done 耗时，重新打开页面不会把计时重置为零。缺少时间的旧记录不编造时间。
